# Economy 0.0.13

### Variant-aware item commodities

- Add exact item commodity identities for stacks whose metadata/components differ, while preserving base-item matching for plain stacks.
- Keep exact variants distinct across Vault counting/extraction, escrow, active orders, trade history, market browse/detail views, and order packet round trips.
- Preserve canonical variant descriptors in trade history so historical exact products can be reconstructed after the last active order disappears.
- Allow another player to open a historical exact product and create a new buy order without already owning that exact stack.

### Networking and correctness

- Bound exact-variant descriptor synchronization both per packet and across the entire Browse refresh: each packet stays below the transport ceiling and total descriptor traffic is capped at 1 MiB, preserving active-order/Vault descriptors ahead of older history when the budget is full.
- Use reset/append semantics for descriptor chunks so multi-packet syncs rebuild the client cache without dropping continuation entries.
- Ignore descriptors that cannot fit the protocol UTF/string budget instead of allowing one oversized entry to break market browsing; the server remains authoritative for commodity resolution.
- Validate ledger-reconstructed stacks against the exact commodity id before using them for details or order creation.

### Testing

- Add packet regression coverage proving descriptor sync chunks stay within the byte budget and preserve all syncable entries.
- Extend real Forge GameTest coverage with a ledger-only exact variant that has no active order and no matching buyer Vault stock, including successful buy-order creation.
