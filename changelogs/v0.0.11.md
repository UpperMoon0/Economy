# Economy 0.0.11

### Addon API platform

- Add the stable `EconomyApi` facade for accounts, orders, market analytics, commodity types, storage providers, and the active server runtime.
- Add loader-neutral Economy and market events, including cancellable balance, transfer, and order-create pre-events plus committed order/trade notifications.
- Add namespaced transaction causes and immutable transaction metadata while retaining legacy transaction-type compatibility.
- Add the public `IOrderManager`, `OrderCreateResult`, immutable trade views, and full commodity identity through `CommodityKey(typeId, commodityId)`.
- Add namespaced, versioned custom commodity codecs with restart-safe persistence and quarantine for unknown/unavailable addon state.
- Add pluggable storage providers with durable reservations, structured provider-owned NBT state, atomic partial-delivery results, and all-or-nothing release semantics.
- Preserve exact item stack state in built-in escrow, including damage, names, enchantments/components/NBT, instead of reconstructing generic stacks.
- Preserve escrow-bearing orders when an addon codec/provider is unavailable rather than silently dropping persisted goods.
- Bind/unbind the public API with the server lifecycle across all supported loader targets.

### Developer documentation

- Add `docs/GETTING_STARTED.md`, `docs/EXTENDING_ECONOMY.md`, and `docs/API_REFERENCE.md` covering dependency setup, lifecycle, events, custom commodities, storage providers, persistence, analytics, and compatibility rules.
- Document transactional escrow invariants, exact provider-owned remainders, structured NBT state, `CommodityKey`, and failure/restart testing requirements.
- Add addon-facing regression coverage for API lifecycle, codec restart round trips, missing-addon quarantine recovery, provider reservation accounting, large structured escrow state, lifecycle events, and same-ID/different-type analytics.

### Server order management

- Add `/economy serverorder list` to show active server orders and their IDs.
- Add `/economy serverorder remove <order-id>` with active-order tab completion so mistaken server orders can be removed safely.
- Show the order ID when a new server order is created.
- Clarify that server orders are server-managed finite orders rather than incorrectly documenting them as infinite.

### Escrow and correctness

- Make provider-backed partial delivery return the exact remaining reservation in the same atomic operation instead of reconstructing remainder state from a delivered count.
- Store exact provider escrow as structured NBT rather than Base64/SNBT packed into one string, avoiding NBT UTF string-size limits.
- Make built-in Vault/Tank reservation release simulate the full restore before committing, preventing partial-release duplication paths.
- Preserve any escrow that cannot be restored during cancelled order creation in quarantine rather than dropping it.
- Resolve the active server level for addon-facing order cancellation so provider-backed SELL orders can be cancelled through the stable API.
- Keep market analytics isolated by full commodity type + product identity.

### Market UI

- Fix reusable search popovers and synchronize dropdown state after outside-click dismissal.
- Show MAX only for sell orders and provide explicit, reactive infinite-buy state in new and edit order dialogs.
- Replace ignored quantity input with an `∞ Unlimited` display for infinite buys.

### Compatibility

- Upgrade to OpenUI MC 0.0.9.
- Keep Fabric 1.20.1, Forge 1.20.1, Fabric 1.21.1, NeoForge 1.21.1, and NeoForge 26.1.2 API/build paths aligned.
