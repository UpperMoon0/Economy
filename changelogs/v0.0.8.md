# NsTut Economy 0.0.8

## OpenUI migration and interface polish

- Rebuilt the Market Terminal, Vault, and Fluid Tank interfaces on OpenUI MC 0.0.6.
- Added responsive layouts, clipped overflow, consistent no-shadow text, semantic status badges, and improved light/dark theme contrast.
- Corrected Portfolio `LIVE` and current-value badge colors, including their hover states.
- Added Coin icons to Product Details and Portfolio chart axes and current-value badges so monetary values are immediately identifiable.
- Added coordinate-derived ellipsis boundaries across Browse, detail orders, Active Orders, Trade History, Portfolio holdings, and Containers so long modded names and values cannot collide with neighboring columns or actions.
- Added clipped ping-pong overflow animation to all Portfolio and Container summary cards so long localized values remain readable without crossing card boundaries.
- Added explanatory tooltips to the Portfolio Net Worth, Liquid Cash, and Vault Assets summary cards.
- Placed Container mode and capacity-status badges on one row and added explanatory hover tooltips for every badge state.
- Added matching mode explanations to the interactive BOTH, INPUT, and OUTPUT controls in the Vault and Fluid Tank screens.
- Wrapped deferred foreground tooltips so virtual-list clipping cannot cut them off or force excessively wide single lines.
- Rebalanced Product Details so the chart, sell/buy order books, personal orders, and action button retain distinct vertical regions.
- Resolved Product Details fluid titles from the client fluid registry, with a readable path fallback instead of exposing raw fluid IDs.
- Replaced bracketed seller labels in the Product Details order books with semantic server/player badges, added Coin icons to clarify order prices, and made each complete badge/currency/price/quantity row ping-pong within its clipped column when it overflows.
- Removed the redundant Browse page title and normalized edit/confirmation dialogs with clear shells, compact spacing, right-aligned styled actions, and Coin-aware transaction totals.
- Added confirmation before cancelling orders from Product Details or Active Orders, including a summary of the goods or coins that will be restored.
- Refreshed authoritative Vault or Tank stock when a valid commodity is selected or entered for a Sell Order.
- Restricted infinite quantity to Buy Orders and clear its state when switching to Sell mode.
- Localized the remaining active-order quantity and server-seller labels.
- Kept Tank transfer annotations aligned with the native processing slot and separated Tank/Vault labels and panels from player inventory slots.
- Added geometry regression tests for the Tank and Vault container screens.
- Fixed a Fabric 1.21.1 stack overflow when rendering Market, Vault, or Tank screens by using the non-recursive 1.21.1 backdrop path with a shared render re-entry guard.
- Completed the NeoForge 26.1.2 port with matching Market, Vault, Tank, networking, persistence, and registry behavior.
- Added 26.1.2 item-model dispatch files, current recipe codecs, and pack metadata so items render and recipes load on the new resource/data formats.
- Fixed 26.1.2 Market viewport sizing and restored vanilla item rendering above themed inventory-slot chrome.
- Prevented container mode controls from flickering while waiting for authoritative server synchronization.
- Made Active Order coin/price/quantity metadata ping-pong as one clipped row instead of truncating the quantity.
- Made long Browse card item names ping-pong inside their title region consistently on every supported game version.
- OpenUI Economy containers now reserve the inventory binding for text/control input and close only with Escape.

## Fluid Tank reliability

- Added direct Forge fluid capability support for pipes and other automation.
- Improved bucket and compatible fluid-container interaction, server synchronization, and transfer behavior.
- Preserved the Tank's market modes and market-connected fluid storage behavior.
- Limited Tank synchronization to tracking clients and removed eager transfer diagnostics from inventory hot paths.
- Kept direct automation independent from market-only storage modes and documented that contract.
- Moved persistent Economy data loading to the overworld-load phase so Fabric and NeoForge never access data storage before the overworld exists.
- Shared server data load, save, and order-matching lifecycle behavior across Fabric, Forge, and NeoForge.

## Packaging and dependencies

- Economy now requires OpenUI MC 0.0.6 or newer.
- CurseForge uploads declare OpenUI MC project `1661978` as a required dependency.
- CI builds an immutable OpenUI MC 0.0.6 release candidate, verifies its published version matches Economy's declared dependency, and then compiles and tests Economy.
- Cross-version CI now compiles and tests every implemented target: Fabric/Forge 1.20.1, Fabric/NeoForge 1.21.1, and NeoForge 26.1.2, with shared parity tests for common UI preferences and formatting behavior.
- Release packaging now collects the production jars for all five supported loader/version targets after the full cross-version gate passes.
- Release metadata now identifies Economy as both a client and server mod.
