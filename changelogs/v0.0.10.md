# Economy 0.0.10

### Market pricing

- Quote fluid market prices per 1,000 mB (one bucket) while retaining mB quantities and storage internally.
- Preserve cent-level bucket quotes as precise per-mB prices in matching, balances, order history, and charts.
- Fractional money values are now shown exactly in balances, confirmations, order history, and charts instead of being rounded.
- Charts scale to the actual data range, so prices below one coin are no longer flattened.

### UI

- Upgrade to OpenUI MC 0.0.8 for container tooltips, wrapped dialogs, reactive search results, and correctly sized search popovers.
- Trade records, charts, and detail requests carry an explicit commodity type, reducing ambiguity when an item and a fluid share the same id. Fully separating same-id item and fluid markets in browse and search is planned for a later release.
- The new order price field is labelled per item or per 1,000 mB depending on the selected commodity type.
- Market actions now report their outcome as in-UI notifications instead of relying on chat:
  - Posted orders show "Order placed"; immediately executed orders show "Order filled" or "Order partially filled".
  - Server validation failures now explain the exact problem (price above maximum, below minimum, too many decimals, quantity over the limit) instead of silently refreshing.
  - A fully executed order is never reported as "rejected" anymore.
  - Cancel and edit failures now use action-specific titles.

### Commands

- Add an explicit per-bucket quote form for fluid server orders: `/economy serverorder buy perbucket <commodity> <qty> <price>`.
- The legacy per-mB server order form is unchanged.

### Compatibility

- Market networking uses protocol v2 (`economy:market_v2`); multiplayer clients and servers should update together. There is no cross-version compatibility with protocol v1 packets: the commodity-type field is always present on the wire.
