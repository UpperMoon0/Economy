# NsTut Economy 0.0.9

## Multi-loader and Multi-version Expansion

- Added official support for Fabric 1.20.1, Forge 1.20.1, Fabric 1.21.1, NeoForge 1.21.1, and NeoForge 26.1.2.
- Updated release publishing to build and deploy separate, loader-specific jars for each supported target with accurate platform and Java runtime metadata.
- Integrated OpenUI MC 0.0.7 container input, geometry, and rendering enhancements across all supported loaders.

## Account Durability & Persistence

- Implemented direct write-through persistence from `BankAccount` transactions to `BalanceStore` / `EconomyAccountData`, marking SavedData dirty on every credit, debit, transfer, and account creation so world autosaves reliably persist account balances on all loaders (Fabric, Forge, and NeoForge).
- Moved persistent Economy data loading to the overworld-load phase so Fabric and NeoForge never access data storage before the overworld exists.
- Shared server data load, save, and order-matching lifecycle behavior across Fabric, Forge, and NeoForge.

## Fluid Tank & Automation Parity

- Enforced atomic bucket transfers on Fabric so nearly full tanks refuse bucket insertion rather than destroying excess fluid.
- Added dynamic bucket resolution for registered modded fluids on Fabric via `BuiltInRegistries.FLUID`.
- Exposed Fabric Transfer API storage (`FluidStorage.SIDED`) with stable per-block-entity instance caching on Fabric 1.20.1 and 1.21.1 for tanks when external automation is enabled in configuration.
- Exposed NeoForge `Capabilities.FluidHandler.BLOCK` on NeoForge 1.21.1 and Forge fluid capability support for tanks when external automation is enabled in configuration.
- Added missing singular `data/economy/loot_table/blocks/tank.json` loot table for Minecraft 1.21.1.
- Fixed a Fabric 1.21.1 stack overflow when rendering Market, Vault, or Tank screens by using the non-recursive 1.21.1 backdrop path with a shared render re-entry guard.

## CI/CD Optimization

- Optimized workflows with OpenUI artifact caching keyed by commit SHA, cutting build setup overhead from minutes to seconds.
- Parallelized multi-loader matrix verification, platform builds, and real-client live join tests across all 5 supported targets.
